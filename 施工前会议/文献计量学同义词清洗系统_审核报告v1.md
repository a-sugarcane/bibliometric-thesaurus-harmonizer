## 一、 评估概述与系统基准

### 1.1 系统研发背景
在生物医学文献计量学中，非受控自然语言关键词的异质性（大小写、单复数、连字符、专有名词缩写及同义离散）导致共现网络节点分裂、拓扑稀疏。目前主流分析软件（VOSviewer、CiteSpace、Bibliometrix）采取“仅提供替换接口，不提供生成算法”的策略，导致超 90% 的研究者依赖人工肉眼制作 `thesaurus` 文件。

针对该痛点，本项目提出“基于形态规则清洗 + NLM MeSH 权威受控词表对齐 + 临床概念防滑坡拦截 + 期刊级审计表导出”的自主可控自动化清洗系统。

### 1.2 评估目标
本报告对该系统在国内外竞品生态中的真实差异化壁垒进行穿透性界定，针对前期技术路线中的潜在漏洞进行双向同行评审审查，纠正二次推论偏差，确立确定性的底层工程重构参数。

## 二、 竞品技术实质与生态位穿透分析

针对市场上常见的文献计量分析工具（特别是具备商业收费属性的工具如 COOC）及其同义词处理能力，进行底层代码机制解构：

### 2.1 机制解构结论
1. **COOC 的核心价值在于“工程胶水与格式集成”**：
   - 支持多源数据库（CNKI、CSSCI、WoS、Scopus）格式归一；
   - 物理覆写原始文本并导出共现矩阵、相似度矩阵（Ochiai、Cosine），服务于 SPSS、UCINET 的传统多元统计分析；
   - 其“同义词合并”本质是**规则执行器**，而非“语义自动化算法”。用户仍需人工在软件外维护两列替换表。
2. **本系统的生态位定位于“算法发现与保真治理”**：
   - 专注解决“面对数千条离散词汇，如何全自动、高可信、可溯源地构建高质量词典”的核心算法空白；
   - 两者在数据流上下游处于互补关系，本系统技术方案不存在被现有竞品覆盖的问题。

## 三、 原始技术路线的系统级缺陷剖析（首轮评审）

对系统原始技术规格书进行反向压力测试，识别出 5 处严重方法学缺陷：

### 3.1 知识库源单一导致药物/基因大面积脱靶
- **原始设计**：仅解析 NLM MeSH `desc.xml`（约 3 万主题词）。
- **缺陷分析**：生物医学文献中大量实体属于具体药物、化合物和靶点（如 `enzalutamide`、`olaparib`）。在 MeSH 体系中，这类专有名词归于 `supp.xml`（补充概念记录，超 30 万条）。仅解析 `desc.xml` 会导致药物词汇出现系统性 OOV（未收录）。

### 3.2 差集拦截算法对合法缩写的误杀
- **原始设计**：采用 Token 差集 $\Delta = (X \cup Y) \setminus (X \cap Y)$ 判定风险，若差集含高危词（如 `resistant`）则阻断。
- **缺陷分析**：合法缩写与其全称（如 `CRPC` 与 `castration-resistant prostate cancer`）进行差集比对时，差集必然包含 `resistant`，导致系统强行阻断最典型的医学缩写合并。

### 3.3 机械末位中心词还原破坏后置修饰与专有名词
- **原始设计**：仅对复合短语末位词执行词形还原。
- **缺陷分析**：忽视了英语医学名词中的后置介词短语修饰结构（如 `carcinoma in situ`、`quality of life`）。机械还原末位词会破坏拉丁化术语（如将 `situ` 误处理）且无法还原首位中心词。

### 3.4 级联传递闭包引发拓扑环路与多对一冲突
- **原始设计**：各模块独立计算映射，缺乏全局收敛。
- **缺陷分析**：多条规则级联（$A \to B \to C$）或反向冲突时，直接输出会导致 VOSviewer 读取出现环路崩溃或单一 Label 多重映射。

### 3.5 频次统计口径与下游图谱二分图去重矛盾
- **原始设计**：在审计表中直接相加合并词频次。
- **缺陷分析**：VOSviewer 会在单篇文献内部执行布尔去重。简单加和得到的“理论频次”高于图谱实际渲染节点频次，导致审稿人对数据一致性提出质询。

## 五、 最终重构架构与模块技术规范（Final Specification）

根据最终审定结果，系统数据流重构为六层确定性流水线：

```
                 ┌────────────────────────────────────────────────────────┐
                 │                 Input: WoS / Scopus / VOS TSV          │
                 └───────────────────────────┬────────────────────────────┘
                                             │
                                             ▼
                 ┌────────────────────────────────────────────────────────┐
                 │ Pass 1: Lexicon Matching (MeSH desc + supp Pruned)     │
                 │ - Exact match lookup (O(1) Hash)                       │
                 └───────────────────────────┬────────────────────────────┘
                                             │ [Missed]
                                             ▼
                 ┌────────────────────────────────────────────────────────┐
                 │ Pass 2: Syntax & Preposition-Aware Lemmatization       │
                 │ - Acronym decoupling (Bi-directional alignment)        │
                 │ - Preposition detection (Head-initial vs Head-final)   │
                 │ - Re-check MeSH lookup                                 │
                 └───────────────────────────┬────────────────────────────┘
                                             │
                                             ▼
                 ┌────────────────────────────────────────────────────────┐
                 │ Pass 3: Risk & Context-Aware Interceptor               │
                 │ - Corpus explicit evidence check (local context)       │
                 │ - Orphan acronym polysemy detection -> Tier 2          │
                 │ - Directed modifier diff (Anti-Concept-Slippage)       │
                 └───────────────────────────┬────────────────────────────┘
                                             │
                                             ▼
                 ┌────────────────────────────────────────────────────────┐
                 │ Pass 4: Graph State Machine & Interactive Review       │
                 │ - Retain full DAG topology in UI                       │
                 │ - Dynamic worst-tier inheritance tracking              │
                 │ - User node/edge curation                              │
                 └───────────────────────────┬────────────────────────────┘
                                             │ [On Export Trigger]
                                             ▼
                 ┌────────────────────────────────────────────────────────┐
                 │ Pass 5: Transitive Reduction & Output Formatting       │
                 │ - Transitive closure flattening                        │
                 │ - Export VOSviewer/CiteSpace/Bibliometrix              │
                 │ - Adaptive granularity frequency audit table           │
                 └────────────────────────────────────────────────────────┘
```

### 5.1 模块 1：数据解析层（`core/parsers`）
- **自适应元数据感知**：
  - 针对 WoS `savedrecs.txt` 和 Scopus CSV，建立篇级 Bipartite 图映射（`Doc_ID <-> Terms`），为篇级去重和局部证据链提取提供数据基底；
  - 针对 VOSviewer `terms.txt`，激活“聚合模式标记”（`is_aggregated_source = True`），下游频次统计与证据链校验自动切换为降级防护策略。

### 5.2 模块 2：双轨知识库层（`core/ontology`）
- **数据源构成**：
  - `desc2026.xml`：提取 30,000+ Descriptor 及全部 Entry Terms，建立主索引；
  - `supp2026.xml`：提取 300,000+ Supplemental Records，建立 `EntryTerm -> SupplementalRecordName` 单射索引；
  - **覆盖优先级**：`desc.xml` 具备绝对命名空间统治权；重叠项强制指向 Descriptor ID。
- **本地词汇剪枝机制（On-demand Vocabulary Pruning）**：
  - 编译器不预载全量 100 万条字典，系统在解析用户输入后，提取输入词及其分词构成的 Token 集合；
  - 仅载入包含该 Token 集合的 MeSH 子图（内存开销由 300MB+ 压缩至 15MB 以内）。

### 5.3 模块 3：形态学与双遍回溯流水线（`core/normalizer`）
- **双遍回溯执行阶梯（Two-Pass Fallback Pipeline）**：
  1. **Pass 1**：全词未经改动，直接检索 MeSH 倒排索引。若命中（如 `quality of life`、`loss of heterozygosity`），直接赋予概念 ID，**立即终止形态切分**。
  2. **Pass 2**：Pass 1 未命中时，启动语法还原：
     - **介词感知还原**：检测是否包含连词/介词（`of`, `in`, `for`, `with`）。若包含，中心词锁定于首个介词前的名词短语，执行词形还原；若不包含，中心词锁定于末位名词；
     - **二次回溯**：完成中心词还原后，重构短语并再次检索 MeSH。若此时命中，赋予概念 ID 并标记为 Tier 1。
- **双向括号缩写解耦**：
  - 计算括号内外字符串的首字母缩写匹配度（Acronym Alignment Score）；
  - 自动识别“全称 (缩写)”与“缩写 (全称)”两种形态，禁止根据括号位置机械切割。

### 5.4 模块 4：风险防护与语境感知拦截器（`core/interceptor`）
- **语料证据链校验（Corpus Evidence Check）**：
  - 缩写映射在执行前，必须检索篇章题录中是否存在显式共同出现（如 `A (B)` 并存）；
  - 若输入为聚合源（无篇章上下文）且缩写属于跨学科高危多义词表（`PCa`, `SAD`, `MDD`），严禁自动放行，强制归入 Tier 2 带有 `[Polysemy Alert]` 标签。
- **定向单向修饰差集拦截（Directed Modifier Difference）**：
  - 废弃双向对称差集；
  - 仅当 $Y$ 在 $X$ 的基础上增加了肿瘤分期、耐药性、严重程度限定词，且两者在 MeSH 中未被明确定义为同义入口词时，触发 Tier 3 强行阻断。

### 5.5 模块 5：DAG 状态机与木桶继承仲裁器（`core/engine`）
- **两阶段生命周期管理**：
  - **审查阶段（Review Phase）**：内存中维护完整的有向无环图拓扑，用户界面展示细粒度跳转。若用户驳回高危边 $B \to C$，系统自动保留安全边 $A \to B$ 并将 $B$ 设为终态。
  - **导出阶段（Export Phase）**：遍历图连通分量，计算传递闭包（Transitive Closure），直接输出扁平化的一跳映射（$A \to C, B \to C$）。
- **最高风险继承机制（Worst-Tier Inheritance）**：
  - 任意路径 $v_0 \to \dots \to v_k$ 扁平化后，直连边 $v_0 \to v_k$ 的风险级别定义为：
    $$\text{Tier}(v_0 \to v_k) = \max_{i=0}^{k-1} \text{Tier}(v_i \to v_{i+1})$$
  - 杜绝安全节点被下游高危操作静默渗透。

### 5.6 模块 6：自适应粒度多格式导出器（`core/exporters`）
- **规范格式支持**：
  - VOSviewer：制表符分隔 `label \t replace by`；
  - CiteSpace：标准 `citespace.alias`；
  - Bibliometrix：`synonyms.csv`。
- **期刊级审计报告（Supplementary Table S1）自适应渲染**：
  - **原生篇级输入**：输出两列频次 —— `Raw Sum of Occurrences`（原始频次绝对和）与 `Document Independent Count`（篇级布尔去重频次）；
  - **聚合输入源**：独立文献数列显式填报 `N/A (Aggregated Source Input)`；
  - **合规声明**：在导出 Excel 页脚与附带文档中嵌入标准 Method 声明，阐明文献计量工具的底层拓扑去重机制，彻底隔绝审稿人质询。

### 7.2 质量验收基准（QA Acceptance Criteria）
1. **零概念滑坡率**：在前列腺癌或抑郁症语料中，`mCRPC` $\to$ `prostate cancer`、`MDD` $\to$ `distress` 的自动合并发生率为 **0%**（必须被强行阻断至 Tier 3）。
2. **缩写召回正确率**：对于语料内存在显式全称对齐的医学缩写（如 `ADT` $\to$ `androgen deprivation therapy`），自动匹配对齐率达到 **100%**。
3. **单射无环性**：导出的 `thesaurus.txt` 经自动化图论校验，环路数为 0，多重映射数为 0，VOSviewer 加载报错率为 0。
4. **性能基准**：在 5,000 篇 WoS 原始题录或 3,000 节点关键词表下，全流程处理时间（包含双遍查表与 DAG 压缩）$\le 3.5\text{ s}$，内存峰值 $\le 45\text{ MB}$。
