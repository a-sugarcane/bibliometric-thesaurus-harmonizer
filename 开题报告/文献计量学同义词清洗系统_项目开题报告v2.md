## 一、 选题依据与核心学术痛点

### 1.1 现实背景
在以 Web of Science（WoS）核心合集为数据源的生物医学文献计量学研究中，关键词（Keywords）共现分析与聚类分析是揭示学科知识结构、前沿演进与热点转变（如共现网络、突变词探测、主题象限图）的绝对基石。

原始题录数据中，关键词由海量作者自由填写，存在天然的表达异质性：
1. **字符串与句法分裂**：大小写不一、单复数并存（`prostate cancer` vs `prostate cancers`）、英美拼写差异（`tumor` vs `tumour`）、连字符有无（`quality of life` vs `quality-of-life`）；
2. **同义术语与缩写离散**：公认临床缩写与全称独立成词（如 `ADT` vs `androgen deprivation therapy`）；
3. **低频长尾噪音**：单次出现词（Hapax Legomena）占比高达 50%~60%，稀释网络度中心性。

### 1.2 现有科研实践的两大核心矛盾
- **痛点一：人工逐行核对的极度低效与视疲劳遗漏**  
  一篇标准文献计量研究（如 1,500 篇文献）包含 1,000 ~ 1,500 个独立关键词。传统方法依赖研究员在 Excel 中肉眼逐行比对并手写 `thesaurus.txt`，通常耗费 3~5 天，枯燥且极易因视觉疲劳发生漏并，严重阻碍科研推进效率。
- **痛点二：同行评审（Peer Review）对“清洗黑箱”与“临床概念滑坡”的双向质询**  
  - 若论文声明“合并了同义词”却未提供清洗清单，审稿人常质疑数据清洗为主观不可复现的“操作黑箱”；
  - 若采用粗暴的算法或规则将不同临床分期（如晚期耐药 `mCRPC`）并入泛指大词（`prostate cancer`），或将症状（`depressive symptoms`）并入器质疾病（`major depressive disorder`），会被审稿人以“缺乏临床常识、抹杀前沿分期演进”为由直接拒稿。

### 1.3 选题目的
构建一套**“先自动合并简单语法变体，再按频次降序供研究者快速可视化筛选存疑词对”**的人机协同轻量级系统，在彻底解放 80% 人工劳动的同时，输出符合国际期刊投稿标准的《同义词规范化清洗审计表（Table S1）》，实现文献计量数据治理的高效性、临床准确性与学术抗辩力。

## 二、 国内外工具链现状与系统真实生态位

为避免夸大宣称，客观厘清现有文献计量软件工具链的真实边界：

| 现有工具类别 | 代表软件 | 真实功能边界与机制局限 | 本系统在工具链中的互补生态位 |
| :--- | :--- | :--- | :--- |
| **网络聚类与渲染软件** | VOSviewer / CiteSpace | **仅提供规则执行接口，不具备候选发现算法**。<br>提供 `thesaurus.txt` 或 `citespace.alias` 导入接口，要求研究者在软件外部自行备好两列替换表。 | **上游治理与候选生成引擎**：<br>为 VOSviewer / CiteSpace 提供开箱即用、零报错、单射无环的高质量规则输入文件。 |
| **R 语言统计包** | Bibliometrix (biblioshiny) | **具备同义词替换参数，但缺乏专业医学本体联动**。<br>`termExtraction()` 支持 `synonyms` 表，但在网页端仍需人工手动填写规则，无医学受控词表辅助判断。 | **临床知识增强与审查助手**：<br>直接导出兼容 Bibliometrix 规范的 `synonyms.csv`，规避 R 语言繁琐的命令行配置。 |
| **通用数据清洗工具** | OpenRefine | **支持编辑距离与聚类，但缺乏医学专科语义理解**。<br>无法理解医学缩写（如识别不出 `CRPC` 对应全称），且无法执行单篇文献级别的二分图二值去重。 | **专科医学领域垂直适配**：<br>内嵌 MeSH 官方知识库与肿瘤/精神专科防滑坡规则，聚焦医学计量场景。 |

**生态位界定**：本系统不替代 VOSviewer / CiteSpace 的绘图聚类功能，亦不盲目追求全自动黑箱替代人类医生，而是定位于**“面向医学文献计量的高精度、可审计、人工在环的关键词规范化候选生成与高效审核工作台”**。

## 三、 核心指导思想与方法学设计准则

根据可行性评估与交叉审查裁决，确立以下 4 项顶层设计准则：

### 准则一：人机协同与抓大放小（“先并简单，高频人筛”）
1. **自动处理低风险区（约占 60%）**：纯大小写转换、纯规则单复数（`patients` $\to$ `patient`）、连字符统一（`quality-of-life` $\to$ `quality of life`），算法高置信度直接自动放行，无需浪费用户精力。
2. **可视化聚焦高风险与高价值区（约占 20%~25%）**：缩写展开、语义近义对齐、高频词微调。将候选对**严格按原始词频降序排列**呈现在交互表格中。用户只需集中精力审查前 100~200 个核心高频词，花 20~30 分钟即可掌控整张图谱 80% 以上的网络连接稳定性。

### 准则二：严守 MeSH 同义粒度（Concept 级同义，非 Descriptor 级同义）
- 彻底纠正将 MeSH 同一 Descriptor 下全部词视为同义词的方法学错误；
- 严格遵循 NLM 官方本体规范：**仅在同一 `ConceptUI` 内部的 Terms 才被视为主干同义词候选**；跨 Concept（哪怕同属一个 Descriptor，如“有氧运动”与“运动”）严格标记为上下位或相关词，**坚决禁止自动合并**。

### 准则三：字段来源溯源与独立保存（DE 与 ID 物理隔离）
- Web of Science 中的作者关键词（`DE`，反映作者原始意图）与扩展关键词（`ID`，算法引文推导词）在数据解析层**分列保存**，禁止无痕混杂；
- 系统默认以作者关键词 `DE` 为清洗主干，将 `DE + ID` 设为敏感性分析备选，保证计量结果的可解释性。

### 准则四：单跳映射与最高风险继承（Worst-Tier Inheritance）
- 放弃过度工程化的复杂图论破环算法；
- 确立**单跳直接映射原则**，禁止不受控的多跳级联闭包（防止微小误差沿传递链放大）；
- 输出文件严格实施 Label 全局唯一单射约束，彻底杜绝 VOSviewer 导入报错。

## 五、 关键算法机制与防御性实现细节

### 5.1 模块 1：数据解析与二值频次引擎（`parsers/wos_parser.py`）
- **字段分列模型**：
  ```python
  @dataclass
  class DocumentRecord:
      doc_id: str                      # WoS 入藏号 (UT WOS:xxx)
      author_keywords_de: Set[str]     # DE: 作者关键词集合
      keywords_plus_id: Set[str]       # ID: Keywords Plus 集合
      combined_keywords: Set[str]      # DE + ID 联合集合
  ```
- **篇级二值计数（Boolean Deduplication）**：
  无论同义词合并前单篇文献内出现多少次变体，合并后该概念在单篇文献内频次计为 1 次，防止虚增网络共现强度。

### 5.2 模块 2：形态学与句法还原层（`normalizer/`）
- **双向括号与缩写首字母对齐（Syntax Cleaner）**：
  提取括号内外两部分字符，运行首字母匹配校验：
  - 若 `ADT (androgen deprivation therapy)` 或 `androgen deprivation therapy (ADT)` 满足首字母缩写对齐，自动解耦全称与别名；
  - 若内部为修饰性文字（如 `depression (geriatric)`），首字母不匹配，禁止截断，完整保留短语语义。
- **中心词单数化与白名单保护（Lemmatizer）**：
  - 介词短语感知：若短语含 `of`, `in`, `with`，优先保留整体；
  - 专科白名单硬防护：针对 `protected_terms.txt` 中的医学词汇（如 `distress`, `genomics`, `metastasis`）以及希腊/拉丁复数（`-ses` $\to$ `-sis`），精准还原，避免误切词根。

### 5.3 模块 3：MeSH Concept 级本体索引（`ontology/mesh_lookup.py`）
- **知识库边界控制**：
  - 核心词表：解析 `desc2026.gz`，构建 `term -> (descriptor_ui, concept_ui, is_preferred)` 哈希字典；
  - 补充化学表：解析 `supp2026.gz`，建立“小分子药物/通用名/代号（如 `MDV-3100` $\to$ `Enzalutamide`）”的直接映射，**严禁按 `<HeadingMappedTo>` 向上强行合并**，杜绝具体药物被化学母核结构吞噬。
- **判决契约**：仅当原词与目标词共享同一 `concept_ui` 时赋予 Tier 1 推荐；跨 Concept 者归入 Tier 2 仅作人工参考。

### 5.4 模块 4：单向特化差集拦截器（`interceptor/risk_rules.py`）
- **废弃对称差集，采用单向修饰扩展检测**：
  - 高危词库：`metastatic`, `advanced`, `castration-resistant`, `mcrpc`, `crpc`, `recurrent`, `refractory`, `mdd`, `distress` 等；
  - 拦截逻辑：仅当目标词比原词“缺少了”上述高危修饰词（即属于特指概念合并至泛指概念）时，判定为概念滑坡，强行阻断至 Tier 3 并标红预警。公认全称缩写等价对通过前序校验安全放行。

### 5.5 模块 5：频次降序交互审查面板（`app.py`）
- **界面核心交互准则**：
  1. 默认展示发生变化的候选对，按 **原始词频（Raw Frequency）降序** 排列；
  2. 顶部设置“高频核心词（$\ge 20$）”、“中频词（5~19）”、“长尾词（2~4）”快速切换标签；
  3. 审查表格支持原地双击修改目标词，支持一键单选/多选确认；
  4. **草稿自动防丢机制**：任何一次勾选实时写入本地 `.draft_checkpoint.json`，刷新页面不丢失审核进度。

### 5.6 模块 6：双轨频次审计表导出（`exporters/audit_reporter.py`）
- 导出包含双轨频次与英文方法学声明条款的 Excel 报表：
  - `Original Keyword (Raw)`：原始脏词
  - `Canonical Keyword (Target)`：规范目标词
  - `Harmonization Tier`：Tier 1 (自动) / Tier 2 (推荐) / Tier 3 (高危拦截)
  - `Rule & Knowledge Base Source`：如 `MeSH Concept (M0017849)`、`Morphology Lemmatization`
  - `Clinical Safety Check`：`Passed` / `Manual Confirmed`
  - `Raw Occurrence Sum`：原始出现总词次和（理论上界）
  - `Independent Document Count`：篇级二值去重独立文献数（**与 VOSviewer 图谱节点度数绝对一致**）
  - `Co-occurrence Reduction`：同篇内布尔去重扣除量（Sum - DocCount）
- **期刊投稿声明模板**：在 Excel 首 Sheet 附带标准英文方法学段落，阐明文献计量图谱基于单篇二分图重新计算的去重机制，堵死审稿人对数据一致性的质询路径。

## 六、 验证方案、金标准构建与验收指标体系

### 6.1 验证数据集
1. **主实验集**：课题组现有的 **1,570 篇前列腺癌与抑郁情绪** Web of Science 纯文本题录数据；
2. **基准对照**：课题组前期人工维护完成的 **1,489 行历史关键词替换表**（`keywords_thesaurus for bibliometrix.txt`）。

### 6.2 400 词对双盲金标准（Gold Standard）基准集构建
在系统运行前，从 1,570 篇文献的词表中抽取 500 个关键词，由两名医学研究人员独立标定，建立包含 400 个词对的测试基准（锁定 40% 作为非公开盲测集）：
- **正向真同义词对（200 对）**：包含大小写、规则单复数、连字符、希腊拉丁词缀、正规医学缩写（`ADT` $\leftrightarrow$ `androgen deprivation therapy`）、同 Concept 词条；
- **反向高危绝不可合并词对（Hard Negatives，200 对）**：
  - 疾病分期：`prostate cancer` vs `metastatic prostate cancer`；
  - 耐药亚型：`CRPC` vs `prostate cancer`；
  - 药物与靶点：`olaparib` vs `olaparib resistance`、`BRCA1` vs `BRCA1 mutation`；
  - 诊断与症状：`depression` vs `major depressive disorder`；
  - 概念上下位：`exercise` vs `aerobic exercise`。

### 6.3 验收考核指标（Pass/Fail Criteria）
系统交付必须严格达到以下量化门槛：

| 评估维度 | 指标项 | 达标合格线 | 测量方法与说明 |
| :--- | :--- | :---: | :--- |
| **临床安全性** | 严重临床假合并数（Severe False Merge） | **绝对为 0** | 在金标准反向词对中，分期/耐药/亚型被误自动合并至大类的发生率必须为 0。 |
| **合并准确率** | 自动合并精确度（Merge Precision） | $\ge \mathbf{98.0\%}$ | 系统标记为 Tier 1 的自动合并中，经医学评审认可的真实同义比例。 |
| **缩写召回率** | 常见临床缩写召回率（Acronym Recall） | $\ge \mathbf{90.0\%}$ | 语料内存在显式展开或 MeSH 唯一缩写的正确对齐比例。 |
| **人工作业提效** | 审核时间节省比例（Time Saved） | $\ge \mathbf{80.0\%}$ | 相比在 Excel 中肉眼排查 1,489 行词表，使用高频筛选面板完成审核耗时缩减至 30 分钟以内。 |
| **下游拓扑兼容** | VOSviewer 导入兼容性 | **100% 成功，0 报错** | 生成的 `thesaurus.txt` 经 VOSviewer 1.6.20+ 真实载入并执行网络共现聚类，零格式冲突、零拓扑环路。 |
| **频次闭环** | 审计表独立文献数与图谱节点一致性 | **100% 闭合** | 审计表导出的 `Independent Document Count` 与 VOSviewer 软件内部节点度数完全一致。 |

## 七、 实施进度规划（两周敏捷闭环）

聚焦手头 1570 篇真实语料的清洗交付，安排 10 工作日（两周）敏捷冲刺：

```
[第 1~3 天] 数据基底与语义对齐
├── 完善 wos_parser.py (提取 UT, DE, ID 建立篇级二分图结构)
└── 重构 mesh_lookup.py (建立 ConceptUI 严格索引与 SCR 药物首选名对照)

[第 4~6 天] 算法精修与单向拦截
├── 精炼 normalizer/ (首字母缩写对齐、介词感知中心词还原、白名单保护)
└── 精炼 risk_rules.py (单向特化差集检测，阻断分期/耐药 concepts)

[第 7~8 天] 高频降序交互面板与导出器
├── 编写 app.py (Streamlit 界面：词频降序、按频段过滤、原地编辑、草稿自动保存)
└── 完善 audit_reporter.py (计算 RawSum, DocCount, 生成 Table S1 Excel 报表)

[第 9~10 天] 真实数据压测与成果验收
```
